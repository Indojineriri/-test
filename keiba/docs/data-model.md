# データモデル設計：出馬表・収集範囲・特徴量の作り方

前回の実装は「3頭のサンプルHTMLでパーサが動く」ところで止まっており、肝心の
**「出馬表が予測の中で何なのか」「どこまで集めれば学習・予想ができるのか」** を
飛ばしていた。この文書でそこを定義する。

---

## 1. 出馬テーブル(entries)とは何か

出馬表は **「結果がまだ確定していないレース結果テーブル」** である。
粒度(grain)は results と完全に同じ：

> **1 行 = 1 頭が 1 レースに出走する1回（= 1 つの "run"）**

results と entries の違いは、着順・タイム・上がり3Fが「確定済みか未定か」だけ。

```
results (過去の run) … finish_pos あり  → 機械学習の「答え(ラベル)」になる
entries (未来の run) … finish_pos なし  → これから「予想したい対象」
```

両者は別エンティティではなく、**同じ run のライフサイクル違い**。
そこで内部では 1 本の縦長テーブル `runs` に統合して扱う（後述）。

### 出馬表の本当の役割

出馬表そのものは18行のメタ情報にすぎない。重要なのは、出馬表が

> **「対象レースに出る horse_id の一覧」を供給する起点**

であること。この18個の horse_id から、データ収集が芋づる式に始まる。

---

## 2. なぜ「1年分のダービー結果」だけでは何もできないのか

ダービー = 3歳・年1回・芝2400m・東京・18頭。これ1レースだけを取ると：

| 問題 | 内容 |
|---|---|
| 行が足りない | **18行のみ**。ML は数百〜数千サンプル欲しい |
| 変動がない | 距離・コース・馬場・格が全頭同じ → 説明変数が動かず学習不能 |
| 実力が分からない | 各馬の「ダービー時点での力量」は**過去走**を見ないと作れない |
| 答えが1つ | 「ダービーで何着だったか」は1馬1回。汎化のしようがない |

予測に必要なのは「ダービーの結果」ではなく、
**出走各馬が “それまでに” どう走ってきたか** である。

### 正しい収集範囲：出走馬を起点にキャリアを辿る

```
[出馬表] 18頭の horse_id
   │  各馬の競走馬ページ(db.netkeiba.com/horse/{id})へ
   ▼
[各馬の戦績] 1頭あたり 5〜10 走 ≒ デビューから前走まで
   │  各戦績行には race_id がある
   ▼
[過去レース結果ページ] そのレースには 同走馬が全頭(8〜18頭)載っている ★
   │  → 拾った全馬・全レースを runs に積む
   ▼
[runs テーブル] ダービー出走馬18頭分のキャリアを集めると…
```

**規模の見積り（ダービー1本を予想するための収集量）**

| 対象 | 行数の目安 |
|---|---|
| ダービー結果だけ | 18 行・条件1種 → 学習不能 |
| 出走18頭 × 各7走 のレース | ユニーク約 120〜150 レース |
| その全レースの全出走馬を runs 化 | 約 **2,000 run 行**（同走馬込み） |

同走馬まで取り込むのがポイント。出馬表18頭を辿るだけで、副産物として
ダービー級の有力馬同士の対戦データが数千行貯まる。これで初めて
「距離が伸びた時」「重馬場の時」「斤量が増えた時」の変動を学習できる。

> 収集を1段で止めない。**entries → 各馬のキャリア → 各レースの全出走馬** の
> 2ホップで、点(1レース)を面(データセット)に広げる。これが①②の本質。

## 3. runs テーブル（統合・縦持ち）

results と entries を縦に積んだ、本ツールの中心テーブル。

| 列 | 説明 |
|---|---|
| `race_id, date` | いつ・どのレースの run か（date が時間順序の基準） |
| `horse_id` | どの馬の run か |
| `finish_pos` | 着順。**未確定(entries)は NaN** |
| `is_target` | この run が「予想したい対象レース」か（entries なら True） |
| `surface, distance, going, grade, track` | レース条件（races から結合） |
| `frame_no, horse_no, impost, jockey_id, ...` | その run の出走条件 |
| `odds, popularity, last_3f, time_sec, passing` | 結果系（entries では NaN/前日値） |

ライフサイクル：
```
未来のレースを予想  : その18頭を is_target=True で runs に追加(finish_pos=NaN)
レースが終わって結果が出る : 同じ run の finish_pos 等が埋まる(過去データに昇格)
```

## 4. 特徴量の作り方：point-in-time（リーク厳禁）

### 何がリークか

各 run の特徴量を「その馬の全成績」から作ると、**未来の情報を使ってしまう**。
例：2024ダービーを予想するのに、2024秋以降の成績を平均に混ぜる＝カンニング。
バックテストの数字だけ良くなり、実戦で全く当たらない典型的な事故。

### 正しいルール

> ある run（基準日 = その run の `date`）の特徴量は、
> **同じ馬の `date` より前の run だけ**から計算する。

これを **各 run 行について** 行う。対象レース(entries)の18頭については、
「出走馬が “その馬の前走まで” にどう走ったか」が自動的に特徴量になる。

```
horse_id=H1 の runs を date 昇順に並べる:
  run#1 (2023-06) 特徴量 = (なし: デビュー戦)          label=着順
  run#2 (2023-09) 特徴量 = run#1 までの集計            label=着順
  run#3 (2024-02) 特徴量 = run#1,#2 の集計             label=着順
  ...
  run#k (2024-05 ダービー, is_target) 特徴量 = それ以前の全走の集計   label=未知 ← 予想対象
```

### point-in-time 特徴量の例（すべて「基準日より前」から算出）

| 特徴量 | 意味 |
|---|---|
| `pit_starts` | それまでの出走数（経験） |
| `pit_win_rate / pit_show_rate` | 勝率 / 複勝率(3着内率) |
| `pit_avg_finish_last3` | 直近3走の平均着順（調子） |
| `pit_best_last3f` | 過去最速の上がり3F（決め手） |
| `pit_days_since_last` | 前走からの間隔（休み明け/詰め） |
| `pit_dist_starts / pit_dist_avg_finish` | 対象距離帯(±300m)での経験と成績 |
| `pit_max_grade_win` | 過去最高格の勝ち鞍（G1/G2…） |
| `pit_avg_field_finish_ratio` | 着順/頭数 の平均（相対的な位置取り） |

これらは results にも entries にも同じロジックで付く。学習(results側、label=着内か)
と推論(entries側、labelを予測)で**同一の特徴量生成器**を通すことで、
train/serve skew（学習時と本番で特徴量の作り方がズレる事故）を防ぐ。

---

## 5. 学習データセットの組み立て

```
runs(縦持ち) ──point-in-time特徴量──▶ サンプル行列 X, ラベル y
                                       ├ 学習用: is_target=False かつ finish_pos 確定
                                       │         y = (finish_pos <= 3) ← 複勝で二値分類 など
                                       └ 推論用: is_target=True の18行 → 複勝確率を予測
```

- **時系列分割**でバックテスト（例：〜2023を学習、2024ダービーで検証）。
  ランダム分割は未来→過去のリークを生むので使わない。
- ラベルの選択肢：複勝(3着内, 二値) / 勝ち(1着, 二値) / 着順(ランキング学習)。
  まずは複勝の二値分類をベースラインにする。

## 6. この設計がコードのどこに対応するか

| 概念 | 実装 |
|---|---|
| runs 統合（results+entries 縦持ち） | `keiba/dataset.py: build_runs_table()` |
| point-in-time 特徴量 | `keiba/dataset.py: add_pointwise_features()` |
| 学習用 (X, y) と推論用 X の切り出し | `keiba/dataset.py: make_training_frame()` |
| 収集の2ホップ（entries→キャリア→全出走馬） | `collect/netkeiba.py: get_past_races()` の race_id 収集 |
| リーク無しの検証 | `tests/test_dataset.py` |

次フェーズ（④示唆出し・⑤予想 = ML + 生成AI）は、この runs + point-in-time
特徴量を入力に組み立てる。
